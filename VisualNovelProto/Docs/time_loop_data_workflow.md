# Time Loop Data Workflow Considerations

이 문서는 타임루프 시스템이 `Story.csv`의 `Index` 컬럼을 활용해 목적지를 구성하는 방식을 설명하고, 시나리오 라이터가 데이터 작성 시 주의할 점을 정리합니다.

## 구조 요약
- `TimeLoopManager`는 런타임에 `DialogueRunner`가 로드한 `Story.csv` 데이터를 검사하고, `Index` 컬럼을 `|` 구분자로 분해해 목적지 키·표시 라벨·분기 라벨·세부 설명을 추출합니다.
- 첫 번째 토큰은 루프 이동에 사용하는 실제 키이며, 같은 키를 가진 노드들은 하나의 목적지로 묶입니다. 나머지 토큰은 UI 표현용 메타데이터이므로 필요할 때만 채우면 됩니다.
- 날짜/시간을 의미하는 문자열(`2024-08-23 09:23`, `0823-0923`, `09:23` 등)은 자동으로 파싱되어 시계 UI에서 시각 정보로 표시하고 정렬에도 활용할 수 있습니다.
- 플레이어가 목적지를 선택하면 `DialogueRunner.RestartAtNode()`가 호출되어 해당 키를 가진 첫 번째 노드로 이동합니다.
- 노드의 `timeLoopKnowledge` 필드는 여전히 유효하며, 특정 노드에 진입했을 때 지식 키를 획득하도록 설정할 수 있습니다.

## Index 작성 가이드
1. **포맷**: `Index` 셀에는 `키|표시라벨|분기라벨|세부설명` 형식으로 작성합니다. 예) `0823-0923|8월 23일 09:23|본관|경비실 침입`. 필요한 정보만 남기고 나머지는 비워도 됩니다.
2. **고유 키 유지**: 첫 번째 토큰(키)은 타임루프 이동에 사용되므로 중복 없이 관리하세요. 동일한 키를 공유한 노드는 하나의 목적지로 취급됩니다.
3. **시간 표현**: 날짜/시간이 포함된 문자열은 자동으로 시계 UI에서 시각 정보로 표시됩니다. `yyyy-MM-dd HH:mm`, `yyyy/MM/dd HH:mm`, `0823-0923`, `09:23` 등 다양한 포맷을 지원합니다.
4. **분기 및 설명**: 두 번째 이후 토큰은 UI에서 분기 라벨과 상세 설명에 사용됩니다. 비워두면 키나 원본 문자열이 자동으로 대체됩니다.
5. **미사용 노드 처리**: 아직 공개하지 않을 노드는 `Index` 셀을 비워두면 목적지 목록에 나타나지 않습니다.
6. **정렬 규칙**: UI 목록은 CSV에 등장한 순서를 따릅니다. 시간 순 또는 장면 순 정렬이 필요하다면 CSV 자체를 원하는 순서로 유지하세요.

## 작업 절차 예시
1. 스토리 CSV에서 각 장면에 적합한 `Index` 값을 작성합니다.
2. Unity에서 `Story.csv`가 참조되는 씬을 재생하거나, `DialogueRunner`가 데이터를 다시 로드하도록 트리거합니다.
3. 인게임에서 타임루프 시계를 열어 새로운 목적지가 표시되는지 확인합니다.
4. 목적지를 선택해 의도한 노드로 점프하는지 테스트합니다.

## UI 연동 팁
- 시계에 목적지 리스트를 노출하고 싶지 않다면 `TimeLoopWatchUI`의 `destinationListRoot`와 `destinationViewPrefab`을 비워 두세요. 매니저는 여전히 `CurrentDestinationKey`와 `TryLoopToIndexKey()` API를 통해 직접 점프할 수 있습니다.
- CSV에 모든 정보를 작성하므로, 커스텀 입력 UI에서 `TimeLoopManager.TryGetDestinationByIndexKey()`로 메타데이터를 읽어 원하는 방식으로 표시할 수 있습니다.
